## Two-school fixture strategy (Task 7)
Cross-school isolation (`L2-DB-44`, `L2-COURSE-06`) cannot be proven by a suite that only ever sees one school — a query scoped to "the" school passes trivially when there is only one row it could possibly match. `global-setup.ts` therefore seeds a second `school` (`RIVAL_SCHOOL`, slug `rival`, upserted idempotently — never truncated, same as the migration-seeded `default` school) and a second teacher (`OUTSIDER`) who is a member of it, with a `course` (and one `deck` under it) seeded directly for `OUTSIDER` in that school — never through the UI, since the point is that the row exists entirely outside the default-school teacher's reach, not that it could have been created by them.

`getCurrentSchoolId()` (`apps/web/app/_lib/school/index.ts`) resolves "the" school by `orderBy(createdAt, id)` and `limit(1)` — with two schools now present, that function would be genuinely ambiguous if anything still called it in a membership context. Nothing does (see that function's own doc comment, `L2-SCHOOL-11`) — every authoring route uses `requireTeacher()`'s `schoolId` instead — but `global-setup.ts` itself had the same latent bug: its pre-Task-7 school lookup was an unordered `select().from(schools).limit(1)`, harmless with one row, silently nondeterministic with two. Fixed by resolving both schools explicitly by their known `slug` (`"default"` / `RIVAL_SCHOOL.slug`) rather than position.

A fourth fixture, `STUDENT` (`student@e2e.test`, role `student` in `default`), was added rather than reusing `TEAMMATE` for the enrolment step of `authoring.spec.ts`'s happy path — `TEAMMATE` is plan 1's deliberately membership-free "signed-in non-member" fixture (`learn.spec.ts`), and giving it a `school_member` row would silently break that other suite's coverage.

**A fifth fixture, `RIVAL_STUDENT` (fix round 1).** Proving `enrollStudent`'s own cross-school check needed a user who fails *only* the school-scope leg of that check, not the role leg too. `OUTSIDER` looked like the obvious id to reuse — it already exists in `RIVAL_SCHOOL` — but it's a *teacher* there, so posting its id fails both `eq(schoolMembers.schoolId, teacher.schoolId)` and `eq(schoolMembers.role, "student")` at once; a test built on it can't tell which predicate is doing the rejecting; removing only the school predicate wouldn't turn such a test red. `RIVAL_STUDENT` (role `student`, same `RIVAL_SCHOOL`) isolates the one predicate the test exists to prove — confirmed directly: with `eq(schoolMembers.schoolId, teacher.schoolId)` temporarily deleted from `enrollStudent`, the hostile-enrolment test failed (the foreign student enrolled successfully instead of being rejected); restored, it passed.

## Gotchas
- `webServer` calls the `next` binary directly — the dotenv-cli `dev` script would load root `.env` and dotenv never overrides preset vars, but bypassing it entirely keeps dev credentials out (`L2-TEST-02`).
- `NEXT_DIST_DIR=.next-e2e`: honored by two lines in `next.config.ts`; without it the e2e server corrupts a running 3070 dev server's `.next`. `.next-e2e` ignored in git/eslint/prettier.
- Login page shadcn `CardTitle` renders a `div`, not a heading — assert on the "Sign in" button instead.
- Never read `ConnectorCopyField` values positionally (`page.locator("code").nth(n)`). The manual-client reveal dialog grew a "Remote MCP server URL" row above the credentials, which silently shifted every index — `createManualClientViaUI` then handed back the MCP URL as the client id and 3 connector tests failed at `/api/oauth/authorize` with an unknown client. `revealedValue(page, label)` anchors on the field's own `aria-label="Copy {label}"` button instead (`L2-MCP-50`, `L2-MCP-52`).
- Setup truncates + reseeds, never drops `backflip_test` — a reused dev server keeps live pool connections (`reuseExistingServer: !CI`).
- `postgres` superuser rights: compose `backflip` user owns the cluster, so `create database` from globalSetup just works.
- `truncate table "user" … cascade` reaches further than it looks: `course.ownerId` is a plain FK to `user` (`onDelete: "set null"`), and Postgres's `TRUNCATE … CASCADE` truncates every table with a FK reference to a named table regardless of that FK's own `ON DELETE` action — so truncating `user` cascade was already wiping `course`/`deck`/`card` (and `oauth_client` and friends) before Task 7 made it explicit. `global-setup.ts` now lists `review_log`, `card_state` (plan 3 Task 6), `enrollment`, `card`, `deck`, `course`, `school_member` in the same statement, children before parents, purely so the *intent* — every authoring row is wiped and reseeded fresh each run — is readable without tracing FK graphs; it changes no actual behavior.
- Running this suite in a minimal/sandboxed Linux environment (no `libnspr4`/`libnss3`/`libasound2` installed, no `apt install` write access) makes Playwright's own Chromium fail to launch (`error while loading shared libraries`). Workaround used here: `apt-get download` the three `.deb`s into a scratch dir (no root needed — this only downloads, does not install), `dpkg-deb -x` each into a local dir, then run the suite with `LD_LIBRARY_PATH=<that dir>/usr/lib/x86_64-linux-gnu` prepended. Not committed anywhere — a per-environment workaround, not a repo dependency.

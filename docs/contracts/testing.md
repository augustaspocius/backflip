## Owns
Automated tests for the web app: unit tooling (Vitest), e2e tooling (Playwright), test-database isolation, essential auth suites.

## Interfaces
- `L2-TEST-01` — `corepack yarn workspace web test` → Vitest, node env, colocated `**/*.test.{ts,tsx}` (excludes `e2e/**`). Config `apps/web/vitest.config.ts` (`@` alias = app root). Turbo task `test`.
- `L2-TEST-02` — `corepack yarn workspace web test:e2e` → Playwright chromium, specs in `apps/web/e2e/`. `webServer` invokes `next dev -p 3170` directly (bypasses dotenv-cli) with explicit env: test `DATABASE_URL`, fixed `AUTH_SECRET`, `NEXT_DIST_DIR=.next-e2e`, no `AUTH_GOOGLE_*` (credentials-only). Config `apps/web/playwright.config.ts`.
- `L2-TEST-03` — e2e `globalSetup` (`apps/web/e2e/global-setup.ts`): create `backflip_test` on `localhost:${POSTGRES_PORT:-5544}` if missing, run drizzle migrations, truncate auth + authoring + review tables (`review_log`, `card_state`, `enrollment`, `card`, `deck`, `course`, `school_member`, `user`, `account`, `session`, `verificationToken`, cascade), reseed five fixtures with bcrypt hashes: `owner@e2e.test` (`OWNER`, `school_member` role `teacher` in the migration-seeded `default` school), `teammate@e2e.test` (`TEAMMATE`, deliberately no `school_member` row at all — the "signed-in non-member" fixture), `student@e2e.test` (`STUDENT`, role `student` in `default`), `outsider@e2e.test` (`OUTSIDER`, role `teacher` in a second school), and `rival-student@e2e.test` (`RIVAL_STUDENT`, role `student` in that same second school). That second school (`RIVAL_SCHOOL`, slug `rival`) is upserted idempotently (`onConflictDoNothing` on the unique slug) alongside the migration-seeded `default` school — neither `school` row is ever truncated. A `course` (title `OUTSIDER_COURSE_TITLE`, exported for the spec to assert on) plus one `deck` under it are seeded directly for `OUTSIDER` in `RIVAL_SCHOOL`, never through the UI — the fixture proving `OWNER` cannot reach a course belonging to a different school. `RIVAL_STUDENT` exists separately from `OUTSIDER` so a test can fail *only* the school-scope leg of a cross-school check without also failing the role leg. No study fixtures are seeded here: `study.spec.ts` inserts its own courses/decks/cards/enrolments (and one card under `OUTSIDER_DECK_TITLE`) through a standalone pg pool, uniquely titled per run, and no users beyond the five above. Never drops the DB (live pools under `reuseExistingServer`).

- `L2-TEST-09` — `corepack yarn workspace web test:e2e:screenshots` → separate Playwright project ("screenshots", viewport 1200×720), never part of the default e2e run. Captures public homepage, admin home, integrations, members, account into gitignored `.screenshots/` at repo root — the single source for page screenshots; one resolution for all. Spec `apps/web/e2e/screenshots.spec.ts`.

## Invariants
- `L2-TEST-04` — e2e never reads or mutates the dev `backflip` database; suite runs only against `backflip_test`.
- `L2-TEST-05` — e2e dev server never shares `.next` with the 3070 dev server: builds into `.next-e2e` via `NEXT_DIST_DIR` (honored in `next.config.ts`).
- `L2-TEST-06` — Scope = essential paths, not coverage. Unit suites freeze auth invariants unreachable e2e — Google `signIn` gate, `tokenVersion` revocation, credentials `authorize`, auth-mode flags, token helpers, capability matrix (`L2-AUTH-05/09/10/11/14/21/29/31/33/34/36/37`). E2e covers `L2-AUTH-13/16/17/24` + sign-out, plus the `/learn` gate states and the invite round-trip (`apps/web/e2e/learn.spec.ts`, `L2-SCHOOL-08/09`): logged-out redirect from `/learn`, signed-in non-member bounced to `/rnl-admin`, member sees the `/learn` shell, teacher sees the Courses link (presence only — the `/learn/courses` list itself is covered by `authoring.spec.ts`), non-owner blocked from `/rnl-admin/school`, and an owner's invite creating then updating a member's role through the UI. E2e also covers the authoring path end to end (`apps/web/e2e/authoring.spec.ts`, `L2-COURSE-06/07/08/09`): create course → add deck (0 cards) → add a markdown card (asserted as a rendered `<strong>`, not literal asterisks) → enrol a student → publish (status flips) — and cross-school isolation against a real second school (`L2-DB-44`): a course seeded for a second school's teacher is absent from the acting teacher's list and 404s at its course and deck URLs (no redirect, no rendered page), with the reverse direction (that teacher opening their own course) also asserted so the 404s are proven to mean "not yours," not "route is broken." A fourth case exercises `enrollStudent`'s own cross-school student check directly, not just the reach checks above: since the candidate `<select>` never offers a foreign student, the test appends an `<option>` by hand (`page.evaluate`) and submits it through the real form/route/action, asserting both the rejection message and a direct `enrollment` query showing zero rows written. Unit suites also freeze the scheduler and queue (`apps/web/app/_lib/srs/schedule.test.ts`, `queue.test.ts`; `L2-SRS-03/04`: exact FSRS outcomes with fuzz off, `interleave` ordering, the UTC day boundary, the daily new-card allowance arithmetic). E2e covers the review loop (`apps/web/e2e/study.spec.ts`, `L2-SRS-06/07/08`, `L2-COURSE-09`): teacher authors/enrols/publishes → student's `/learn` row reads "1 due" → reveal, rate Good → "Nothing left to review." → "Nothing due", with pg asserting one `review_log` + one `card_state` row (due in the future), then the teacher's progress page counting this course only; a student bounced off `/learn/courses`; an enrolled draft course absent from `/learn` and its `/learn/study/<id>` redirecting to `/learn`; the daily new-card cap (20 cards introduced today → an unseen card is held back: "Nothing due", empty session; the same introductions backdated before UTC midnight → "1 due"); and hostile `answerCard` calls made by rewriting the real server-action POST (`page.route`, `next-action` header) with one case per guard leg (rival school unenrolled, rival school enrolled, same school unenrolled, same school draft) plus non-integer grades, each asserting the interception fired, the failure is shown and the session advances, and zero rows written. Tests exercise real exported modules — no logic copies in tests.
